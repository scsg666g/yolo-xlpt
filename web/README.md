# YOLO 模型训练平台

独立于 Ultralytics 源码的训练任务控制台。平台通过受控参数调用现有 `yolo` CLI，并读取 `args.yaml`、`results.csv` 和权重文件。平台业务集中在 `web/`，训练行为仍取决于实际执行服务器上的 Ultralytics 版本与依赖环境。

本说明面向页面使用和平台开发；首次安装见 [项目首页](../README.md)，远程配置见 [Agent 说明](agent/README.md)，服务维护见 [部署说明](deploy/README.md)，架构和当前缺陷见 [项目分析](../docs/project-analysis.md)。当前平台版本为 **1.1.0**，配套远程 Agent 为 **1.8.0**。

## 功能

- 训练任务创建、排队、启动、停止、断点续训、重新训练、克隆和历史任务导入
- 一条任务保留多次独立训练运行，各自保存参数快照、指标、日志和权重
- 每条训练任务对应一张 React Flow 无限画布
- 实时训练进度、指标曲线、日志、GPU 设备和训练产物
- 在训练画布测试检测模型：多图上传、置信度筛选、原图与检测结果对比、双击放大及下载结果图
- 按本机活动任务的 GPU 编号排队；远程同编号 GPU 不占用本机设备，不限制平台外进程
- 训练参数白名单和模型/数据集目录边界检查
- 本地数据集文件夹上传、格式检查、自动生成配置和选中数据集
- 平台上传数据集的规模、类别、警告与任务引用管理，以及未引用数据集的安全删除
- 服务重启后按进程身份尝试恢复管理，身份不匹配时明确标记中断
- 按服务器折叠的算力监控，服务器搜索、编辑、独立 Token 与 Agent 接入
- 可选远程训练，统一任务操作、指标日志、产物预览下载与异步文件清理
- 任务中心、算力资源、训练画布与实验对比的响应式布局，以及核心弹窗的 Esc 关闭、焦点限定和焦点恢复
- 侧栏健康状态和平台设置弹窗，查看版本、数据库、调度错误、文件清理与模型测试线程

## 目录

- `frontend/`：React、TypeScript、React Flow 和 ECharts
- `backend/`：FastAPI、SQLAlchemy 和训练调度器
- `data/`：SQLite 数据库、日志和平台训练产物，不提交 Git
- `deploy/`：systemd 服务模板
- `agent/`：无第三方依赖的算力监控与可选远程训练 Agent 和部署说明

## 页面与任务操作

| 页面 | 地址 | 用途 |
| --- | --- | --- |
| 任务中心 | `/` | 创建、排序、重命名、克隆、训练操作和回收站 |
| 训练画布 | `/tasks/<task-id>/canvas` | 查看选中 Attempt 的配置、进度、指标、日志与产物 |
| 实验对比 | `/compare` | 选择任意历史 Attempt，包括同一任务的不同运行；当前浏览器可将上限设为 2～8 |
| 算力资源 | `/compute` | 查看本机与远程资源、节点状态和接入配置 |
| 数据集管理 | `/datasets` | 查看平台上传数据集、任务引用并删除未引用数据集 |
| API 文档 | `/docs` | 接口参数与响应格式 |

任务中心每 3 秒轮询任务列表；后端虽提供 `/api/stream` SSE，当前前端尚未使用。前台训练画布每 3 秒刷新，页面进入后台时暂停画布轮询。实验对比每 5 秒刷新，选择器列出每个任务的全部历史 Attempt，并按运行 ID 加载参数快照和指标。平台设置可将当前浏览器的同时对比上限设为 2～8，默认 4；列数与已选 Attempt 数量一致，窄屏时表格保持可读宽度并横向滚动。

侧栏在页面可见时每 30 秒请求一次 `/api/health`，并区分正在检查、在线和异常。“平台设置与状态”弹窗可切换当前浏览器主题、设置实验对比数量上限，显示平台版本、数据库、训练调度器、本机文件清理、模型测试线程、平台实例、数据库延迟和训练输出目录，也支持手动重新检查。调度循环任一轮抛出异常时，后端记录异常并在健康接口中返回当前与最近错误；页面不再把“线程存活但本轮失败”显示为正常。这仍不能代表某个训练一定持续产生输出。

| 操作 | 允许的任务状态 | 行为 |
| --- | --- | --- |
| 首次启动 | `draft` | 创建新 Attempt 并排队 |
| 继续训练 | `stopped`、`interrupted` | 要求可用 `last.pt` 和尚未完成的目标轮数；创建新 Attempt |
| 重新训练 | `failed`、`stopped`、`interrupted`、`completed` | 使用当前配置从头运行，保留旧 Attempt |
| 修改参数或输入路径 | 非 `queued`、`starting`、`running`、`stopping` | 修改任务配置，不改写历史参数快照 |
| 重命名 | 未移入回收站的任务 | 可在训练时修改，仅改变展示名称并记录事件 |
| 克隆 | 未移入回收站的任务 | 创建草稿，复制配置、执行节点与画布布局，不复制训练结果 |
| 移入回收站或永久删除 | 非排队、启动、运行、停止中 | 先停止活动任务，文件清理规则见下文 |

平台参数目录来自 `ULTRALYTICS_ROOT/ultralytics/cfg/default.yaml` 的训练、验证、分割、分类和超参数分组，不等于 `YOLO_BIN` 所属环境的实时能力探测。创建和编辑时会拒绝空白任务名、空白优化器、重复 GPU 编号，并对预设参数与自定义参数执行类型、有限数值和范围校验。修改参数时还可提交最多 30 项自定义参数；不能覆盖平台管理的模型、数据、输出目录、设备或续训控制字段。未被实际 YOLO 版本支持的参数仍会导致训练失败。

API 可接受 `detect`、`segment`、`classify`、`pose`、`obb`，但当前数据上传仅支持检测标签，资源选择以 YAML 数据配置为主，实验对比的主要指标是检测框指标。不能据此认定五种任务类型已经具有同等完整的页面支持或训练验收。

## 图片模型测试

在训练画布的 `best.pt` 卡片点击“测试模型”，或双击旁边的“模型测试”节点，即可打开测试弹窗；模型权重详情内也提供相同入口。平台会记录打开测试时的画布 Attempt 和实际权重来源 Attempt；有效 `best.pt` 可能来自更早的 Attempt。弹窗分为“新建检测”和“历史记录”两个页签。

1. 点击“点击或拖入图片”选择一张或多张 JPG、PNG、WEBP、BMP 图片，或将图片拖入弹窗，看到“松开添加图片”后松开鼠标。已有图片时可继续追加，点击缩略图右上角移除单张图片；添加和移除会清除旧检测结果，需要重新检测。每次最多 10 张、总计 100 MB，单张不超过 20 MB 和 2000 万像素；不支持拖入文件夹，检测期间禁止添加和移除。
2. 调整置信度 Conf 阈值（0.01～1，默认 0.25）和 NMS IoU 阈值（0.01～1，默认 0.70），点击“运行检测”。修改参数后，页面会保留并标明旧结果使用的参数，直到重新检测完成。
3. 点击左侧缩略图切换图片，对照原图和带检测框、类别与置信度的结果。结果区同时显示当前图的逐目标类别和置信度、整批类别统计、平均置信度以及模型加载/预处理/推理/后处理耗时。双击图片或点击放大按钮可全屏查看。
4. 点击“当前结果图”保存当前图片的 JPEG 检测结果；点击“下载全部”获取包含全部结果图和 `detections.json` 结构化数据的 ZIP 文件。提交后每次检测都会创建独立记录，再次检测不会覆盖旧记录。

检测完成后显示多图汇总，例如“共 5 张：3 张检测到目标，2 张未检测到”。切换图片时，结果区分别显示绿色“检测到 X 个目标”或“当前置信度阈值 0.25 下未检测到目标”；未检测到时可适当降低阈值重新检测，不代表图片中一定没有目标。提示使用本次检测实际采用的阈值，调整滑块后须重新检测才会更新结果。检测失败单独显示红色状态和错误原因，不计入未检测到的图片。

当前支持目标检测任务的 `.pt` 权重，在选中运行结束或停止后使用。弹窗会标明权重所属 Attempt，并显示该运行历史最高 mAP50-95 及对应 Epoch（存在指标记录时）。推理由中心平台的 `YOLO_BIN` 同环境 Python 在 CPU 上串行执行，输入尺寸为 640，不占用训练 GPU；大模型可能需要更长时间，单批推理最多等待 5 分钟。

“历史记录”按当前任务列出持久化记录，可查看全部记录或只筛选当前 Attempt。选中记录后可以查看保存的原图和结果、下载 ZIP、显式删除记录；只有中心仍能取得与历史记录 SHA-256 和大小完全一致的权重字节时，才可以载入原图、阈值和该精确权重版本创建新记录。精确权重已失效不会影响已有结果的查看和下载，但不能使用该记录重测。

测试记录元数据保存在 SQLite 的 `model_tests`、`model_test_images` 表，规范化原图、结果图、日志、汇总和 ZIP 等持久文件保存在 `PLATFORM_DATA_ROOT/model-test-history/<任务ID>/<测试ID>/`。模型副本和执行中间文件位于 `PLATFORM_DATA_ROOT/model-test-work/<测试ID>/`；服务恢复时会校验固定权重的 SHA-256 和大小，有效副本保留并重新排队，终态、缺失或校验失败的副本才清理。创建时会在历史目录写入可恢复的容量预留，按权重副本、浏览器上传、规范化原图、结果图和 ZIP 的保守峰值计算；完成、失败或取消后改按实际文件大小计入用量。`PLATFORM_MODEL_TEST_HISTORY_QUOTA_BYTES`（默认 20 GiB）限制全部历史，`PLATFORM_MODEL_TEST_TASK_QUOTA_BYTES`（默认 5 GiB）限制每个训练任务，`PLATFORM_MODEL_TEST_MIN_FREE_BYTES`（默认 2 GiB）保留磁盘余量，`PLATFORM_MODEL_TEST_IMAGE_RESERVE_BYTES`（默认 64 MiB）控制单图片预留；值均为字节，前三项设为 `0` 可有意关闭对应限制。只有尚未提交完成的 `uploading` 记录会在 24 小时后过期；完成、失败和取消记录不会按时间自动删除。

关闭弹窗时，已进入 `preparing`、`queued` 或 `running` 的检测会继续在服务端运行，浏览器只停止当前请求和轮询；重新打开后可在历史记录中查看进度或结果。如果记录仍处于 `uploading`，页面会请求放弃未完成上传并将记录标记为已取消；若启动请求已经先成功，放弃请求会被拒绝，检测仍会继续。关闭时处于上传与提交交界的记录，应以历史页显示的最终状态为准。需要终止已提交的活动检测时，须在历史记录中显式删除；删除会取消处理并清理该条记录的原图、结果和下载文件。模型测试不修改原权重和训练产物。

远程权重通过现有 Agent 产物传输接口为新测试做准备。推理和持久化存储都在中心完成，所以测试完成后，即使远程 Agent 离线，已有原图、结果图和 ZIP 仍可查看或下载。该历史功能没有单独新增 Agent 协议，但当前平台的远程训练入口统一要求 Agent 1.8.0。

## 多服务器算力监控

「算力资源」默认注册并展示本机。每台服务器是一组可折叠的资源面板：收起时显示名称、地址、状态和 GPU 摘要，展开后保留原有 GPU、显存、功耗、温度、时钟、进程及主机详情。

### 添加与接入

1. 点击“添加服务器”，填写名称、地址 / IP（可选）、备注（可选），选择上报间隔及是否启用监控。地址仅用于显示，不是 SSH 连接目标。
2. 保存后确认“中心平台地址”可从远程服务器访问，下载 Agent 与专属配置。当前浏览器地址只是初始值，可按网络情况修改。
3. 将两个下载文件放到远程服务器，执行 `chmod 600 agent-config.json`，先用 `--check-config` 离线检查路径和训练环境，再用 `--once` 验证中心连接。
4. 验证成功后执行 `python3 monitor_agent.py --config agent-config.json` 持续上报，回到页面刷新并展开对应服务器。

Agent 使用 Python 3.9+ 标准库，当前面向 Linux/POSIX，依赖 `fcntl` 和 `/proc`；NVIDIA GPU 需要驱动和 `nvidia-smi`。不需要安装完整平台或提供 SSH 用户、密码。终端关闭后前台 Agent 会退出，长期运行可配置 systemd，详见 [Agent 部署说明](agent/README.md)。

### 页面操作与状态

搜索支持名称、地址、主机名和备注；支持按状态筛选、全部展开或折叠。页面默认每 5 秒刷新，可暂停自动刷新或立即刷新；远程指标的实际更新频率取决于 Agent 上报间隔。收起的远程服务器只读取摘要，详情在展开时加载。

| 状态 | 含义 |
| --- | --- |
| 等待接入 | 尚未收到有效上报，或重新生成 Token 后等待新的 Agent 上报 |
| 在线 | 已收到有效上报，采样未过期；没有 GPU 也可以在线 |
| 离线 | 中心最近接收时间 `last_seen_at` 超过 `max(30, 上报间隔 × 3)` 秒，下方显示最后一次数据并标记过期 |
| 已禁用 | 中心拒绝该节点所有 Agent 认证接口，页面保留此前数据；不会直接停止训练 |

名称、地址、备注、启用状态、上报间隔和最近采样保存在中心数据库，刷新页面或换浏览器仍然保留。展开状态保存在当前浏览器，不跨浏览器同步。中心以自己的 `last_seen_at` 判定连通性，不会因远程时钟落后而把刚收到的上报误判为离线；远程时钟超前过多仍会在上报校验阶段被拒绝。

### 编辑、Token 与移除

本机支持修改显示名称、地址和备注，不能禁用或移除。远程服务器还可以调整上报间隔、禁用监控、查看接入步骤、重新生成 Token 或移除。

每个节点使用独立 Token，中心数据库只保存哈希，创建或重置后仅在当前接入窗口提供配置下载。配置丢失时需要重新生成 Token；旧 Token 立即失效，必须替换远程配置并重启 Agent。调整上报间隔后，Agent 在后续成功上报的响应中接收新间隔，通常无需重启。

移除服务器前须先清理关联任务，包括回收站中的任务；移除后节点资料和最近采样删除，Token 失效。移除本身不清理远程文件或停止训练进程。重新添加会生成新的节点和 Token。

Agent 默认只监控算力；配置 `enable_training: true` 并设置训练环境和允许目录后，可在新建任务中选择远程执行服务器，填写该服务器上模型、数据 YAML 和输出目录的绝对路径。`yolo_bin` 默认使用 `PATH` 中的 `yolo`，`training_cwd` 未配置时使用 Agent 配置文件所在目录。任务卡片显示执行服务器；停止、克隆、重新训练、回收站和历史运行沿用本机任务入口。数据集上传仍保存到中台，不自动同步到远程服务器。

当前中心要求 **Agent 1.8.0** 才能接受新的远程训练，并在创建、启动、续训、重新训练及领取时同时校验节点在线和 `training.ready`。Agent 未就绪时也会暂停领取。远程任务的 `last.pt` 元数据同步后，可对已停止或中断的任务继续训练，新 Attempt 保留旧文件；总轮数和数据集必须与上一次运行一致。产物列表由 Agent 扫描，预览或下载时分块传输并校验后缓存到中台 `PLATFORM_DATA_ROOT/remote-artifacts/`。

Agent 1.8.0 使用同一系统用户私有状态目录中的层级输出根锁：相同或父子输出根互斥，不相交的兄弟根可以并行；该保护不依赖两份配置的 `training_lock_file` 文本恰好一致。若两个 Agent 另外共用同一个传统锁文件，不相交的输出根也会被该锁串行。workspace owner 由稳定 `node_id` 生成，共享输出根存在其他存活 Agent 时会拒绝永久删除。同机多 Agent 应使用同一专用系统账户；不同账户即使共享传统 `training_lock_file`，也无法共享 workspace 删除 owner 登记。

模型测试历史没有改变上述 Agent 协议和版本要求。使用远程权重新建测试时，若中心已有完整且匹配的权重缓存，Agent 离线也可继续；只有首次或需要重新传输产物时才要求 Agent 在线。测试完成后，历史原图、结果和下载包由中心保存，Agent 离线时仍可使用。

当前中心与 Agent 1.8.0 的预设参数集合一致。中心会在创建、编辑、启动、续训和重新训练时对照节点上报的能力，旧 Agent 缺少参数时会明确提示升级或移除参数。远程 YOLO 版本本身仍可能不支持某些新参数，应继续核对实际命令和 `args.yaml`。

远程任务移入回收站或恢复只改变记录。永久删除提交后不可恢复，回收站显示“远程清理中”；Agent 只清理该任务的各次 Attempt 与日志，确认成功后平台删除记录及缓存。离线时等待接入；清理失败保留记录并提供重试，不能恢复可能已经部分删除的文件。相关路径必须在 Agent 允许目录内；Attempt 的输出根目录不存在、允许目录失效或挂载离线时，清理会明确失败并保留记录。后端启动时自动创建节点和文件操作队列表。算力进程必须同时匹配 `execution_node_id` 和 PID 才会关联到训练，不同节点上的同号 PID 不会串任务。部署和维护见 [Agent 说明](agent/README.md)。

远程任务发出正常停止请求后，若持续 `stopping` 至少 30 秒，训练画布会显示“解除占用”。必须先登录远程服务器，确认当前 Attempt 的 YOLO 进程已经结束后才能使用。它只把 Attempt 标记为中断并解除中心节点占用，不会终止远程进程；误确认可能导致新旧训练同时占用 GPU。

```bash
cd /path/to/yolo-forge/web  # 替换为实际 checkout
conda activate yolo

# 训练框架和后端都安装到实际运行的环境
python -m pip install -e '../ultralytics'
python -m pip install -e './backend[dev]'
export YOLO_BIN="$(command -v yolo)"

cd frontend
npm ci
npm run build

cd ../backend
python -m uvicorn app.main:app --host 0.0.0.0 --port 18088 --workers 1
```

打开 `http://服务器地址:18088`。API 文档位于 `/docs`。

示例的 `/path/to/yolo-forge` 需替换为实际 checkout，Python 和 Conda 环境也由部署机决定。默认路径从源码目录推导，需要覆盖时参考 [环境变量示例](.env.example)。`YOLO_BIN` 未设置时先查找当前 Python 环境的 `yolo`，再查找 `PATH`。直接启动 Uvicorn 不会自动读取 `.env`；应显式导入环境变量，或按 [部署说明](deploy/README.md) 使用对应实例的 systemd 模板。仅改变 `PLATFORM_DATA_ROOT` 不会改变默认数据库地址，迁移时须同时设置 `DATABASE_URL`。不要覆盖已有配置文件。

已安装依赖、构建过前端时，只需进入 `web/backend/` 启动后端。前端修改后重新构建，后端修改后重启服务；出现端口占用时先确认原进程或 systemd 服务，避免重复启动。

> 当前调度器运行在 API 进程内，因此 Uvicorn 必须保持 `--workers 1`，同一状态目录和数据库只能由一个后端实例管理。若以后部署多个 API 实例，应先拆分调度与文件操作，设计进程所有权及数据库/队列协调机制。

## 上传数据集

在「创建训练任务 → 数据集配置」旁点击「上传数据集」，或在「数据集管理」页点击同名按钮，选择最外层文件夹。目前支持 YOLO 目标检测，窗口中会显示目录格式、标签示例、类别编号和文件限制：

```text
我的数据集/
├── images/
│   ├── train/
│   └── val/
└── labels/
    ├── train/
    └── val/
```

图片与标签应同名，标签每行格式为 `类别编号 中心x 中心y 宽 高`，坐标归一化到 0～1，宽高大于 0。类别名称每行填写一个，对应编号从 0 开始；也可从上传目录中的 `data.yaml` / `data.yml` 的 `names`，或 UTF-8 编码的 `classes.txt` 读取。无标签或空标签图片可作为背景图，完成后会显示提醒。

服务器保留原文件夹名称（支持中文），保存到项目的 `数据集/<原文件夹名>/`。系统自动生成 `data.yaml`，其中 `path` 是该文件夹的实际绝对路径，`train` / `val` 分别为 `images/train` / `images/val`；原配置中的其他服务器路径会被替换。上传完成后自动选中该数据集，同名目录会拒绝上传，不覆盖已有内容。

支持 JPG、JPEG、PNG、BMP、WEBP、TIF、TIFF，单张图片最大 256 MiB，单个标签或配置文件最大 4 MiB，总大小最大 50 GiB / 20 万个文件，类别最多 1000 个且名称不能重复。`images/train` 和 `images/val` 都须包含图片，同一划分下不能出现相同相对文件名但不同扩展名的图片。浏览器不能传递空目录，因此缺失的空标签目录会自动补齐。系统文件和缓存会忽略；其他不符合格式的文件会提示整理。建议用 Chrome 或 Edge 选择文件夹。

上传先保存到 `PLATFORM_DATA_ROOT/dataset_uploads/`，校验后在数据集根目录的隐藏发布目录中构建完整副本，最后一次原子重命名为最终数据集目录。因此未完成的副本不会被任务资源发现；响应丢失或发布中断后可重试，平台会恢复已成功发布的结果或重新构建。发布期间两份数据同时存在，同一磁盘部署建议预留接近数据集两倍的空间及额外余量；标称 50 GiB 上限不代表剩余 50 GiB 就一定能完成发布。

上传窗口保持打开时，可以暂停或在连接中断后重试，已经传完的文件无需重复上传。关闭窗口会清理临时上传，刷新页面后需要重新选择；超过 24 小时未使用的上传记录会在后续上传时清理。数据在图片、标签和类别检查通过后才会加入可选数据集，完成响应丢失时重试不会重复保存。

### 数据集管理

`/datasets` 只列出由平台成功上传并保留管理标记的数据集。页面汇总数据集数量、图片数和空间占用，支持按名称、路径或类别搜索，以及按“可删除/已引用”筛选。每个数据集显示训练与验证图片、标签、类别、背景图、警告和引用任务。手工放入 `数据集/` 的目录不带平台标记，不会在该页显示或被删除。

删除前后端会重新检查本机任务引用；普通任务和回收站任务都会阻止删除，软链接等价路径也会被识别。远程任务的路径由远程 Agent 边界管理，即使字符串相同也不计作本机引用。删除会先原子地将数据集移入隐藏清理区，使其立即不再被资源列表或新任务发现，再递归删除文件。若后续文件清理失败，接口会返回错误，平台启动或创建新上传时会再次尝试清理隔离目录。此操作不可恢复。

## 训练目录

一条训练任务对应多次运行，每次启动、续训或重新训练生成新的 `Attempt`。新运行默认写入：

```text
web/data/runs/<task-type>/<task-id>/attempt-001/
web/data/runs/<task-type>/<task-id>/attempt-002/
```

各次运行的参数快照、`results.csv` 和权重分别保存；`weights/best.pt` 与 `weights/last.pt` 可从对应运行的训练产物中查看和下载。实际生成哪些产物由训练框架和保存参数决定。

断点续训使用上一次运行的 `weights/last.pt`，需要任务处于已停止或已中断状态、检查点存在且目标轮数大于已完成轮数；从检查点保存的训练状态继续。远程续训还需要 Agent 1.3.0 和已同步的检查点元数据，总轮数及数据集须保持与原运行一致。重新训练则使用当前任务配置从头启动。

已有的 `ultralytics/runs/**/args.yaml` 会在服务启动或点击导入时扫描，只导入 `mode: train` 的记录。扫描导入本身不会移动、删除或改写原训练文件；状态主要根据结果中的已完成轮数判断，不代表平台已接管原来的训练进程。导入时缺失的模型、数据路径需要修正后才能再次训练。回收站与文件清理规则见下文。

### 回收站与永久删除

移入回收站仅隐藏任务并保留文件和模型测试历史，刷新或重启后仍然隐藏；普通软删除任务可以恢复，恢复后测试历史重新可见。任务状态切换时会取消其仍在执行的模型测试。永久删除接口返回 HTTP 202，表示清理已受理，不表示所有文件已经删除。

| 执行位置 | 清理执行方 | 成功与失败 |
| --- | --- | --- |
| 本机 | API 进程中的后台删除线程 | 成功后删除记录；失败在回收站保留原因并允许重试；重启后重新处理未完成清理 |
| 远程 | 对应节点的 Agent 文件操作线程 | Agent 确认成功后删除记录与中心缓存；离线等待，失败保留原因并允许重试 |

一旦提交永久删除，清理中或清理失败的任务都不能恢复，因为文件可能已部分删除。清理目标包括任务各次运行结果、独立日志、本机运行时配置和中心保存的全部模型测试历史；历史导入任务的原始结果也可能被删除。本机删除在验证路径边界时保留末端符号链接本身，遇到顶层或目录树内的符号链接都不会跟随到外部目标。中心历史清理失败时任务保留为可重试的清理失败状态，不会提前删除任务行。远程任务还需要 Agent 在线清理远程 Attempt 和日志，成功完成整套永久删除后才移除任务记录。输入模型和数据集应放在独立资源目录，不应放在准备清理的任务输出目录内；远程 Agent 会保护已登记的输入路径，但没有登记的外部引用不在保护清单中。

### 日志和运行数据

训练日志默认保存到当前 checkout 的 `web/data/log/`，也可用 `PLATFORM_LOG_ROOT` 指定其他目录。文件名格式为：

```text
YYYYMMDD_<task-id>_attempt-001.log
YYYYMMDD_<task-id>_attempt-002.log
```

例如 `20261012_<task-id>_attempt-001.log`。日期前缀配合任务 ID 和运行编号，避免同一天多个任务覆盖日志。日志保存训练命令和训练进程输出；Uvicorn 访问日志仍由启动终端或 systemd journal 收集，不自动写入此目录。

### 日志查看与导出

日志窗口展示选中 Attempt 的日志尾部，本机前端请求 `tail=240`；日志接口允许的 `tail` 范围是 20～5000，默认 400。远程 Agent 默认上报最近 100 行，中心保留最近一次尾部，不累计为完整日志；增大 `tail` 不能取回未上传的远程历史输出。

| 控件 | 当前实现 | 使用限制 |
| --- | --- | --- |
| 搜索 | 筛选页面已经收到的日志行 | 不搜索服务器完整文件 |
| 自动滚动 | 新尾部到达时滚动到末尾 | 刷新周期来自前台画布轮询 |
| 复制全部 | 将当前收到的所有行复制到剪贴板 | 不复制完整文件，也不只复制搜索结果；HTTP 内网地址可能没有 Clipboard API，当前缺少降级和错误提示 |
| 下载日志 | 将当前收到的行生成浏览器 Blob 文件 | 只下载尾部；临时 URL 立即释放，存在浏览器兼容隐患，尚未逐浏览器验证 |

当前没有独立的完整日志下载接口，也尚未清理日志中的 ANSI 终端控制序列。HTTPS 可以满足 Clipboard API 的安全环境要求，但不能改变导出仅包含尾部的事实。需要完整日志时，到实际执行服务器获取窗口显示的日志文件；不要把远程路径当成中心机器的文件路径。远程日志位置见 [Agent 日志说明](agent/README.md#日志断网与停止原因)。这部分是现有缺陷说明，不是已经完成的修复。

| 内容 | 默认位置 |
| --- | --- |
| 数据库、服务器资料及最近算力采样 | `web/data/platform.db` |
| 每次训练产物 | `web/data/runs/<task-type>/<task-id>/attempt-NNN/` |
| 每次训练的运行时配置 | `web/data/task_runtime/<task-id>/attempt-NNN/` |
| 按需传输的远程产物缓存 | `web/data/remote-artifacts/` |
| 临时数据集上传与完成回执 | `web/data/dataset_uploads/` |
| 持久模型测试原图、结果和下载文件 | `web/data/model-test-history/<task-id>/<test-id>/` |
| 模型测试权重副本与执行临时文件 | `web/data/model-test-work/<test-id>/` |
| 训练日志 | `web/data/log/YYYYMMDD_<task-id>_attempt-NNN.log` |
| 上传数据集及生成的 YAML | `数据集/<原文件夹名>/data.yaml` |

运行数据根目录可通过 `PLATFORM_DATA_ROOT` 调整，也可以单独设置 `PLATFORM_RUNS_ROOT`、`PLATFORM_RUNTIME_ROOT` 和 `PLATFORM_LOG_ROOT`；数据库可通过 `DATABASE_URL` 指定。迁移时需一起保留数据库和相关文件，并核对绝对路径。模型测试历史由数据库索引和 `model-test-history/` 文件共同组成，两者必须成套备份、恢复；SQLite Backup API 不包含该目录，也不会冻结并发文件变化。需要严格匹配时，先停止或静默目标服务并确认没有模型测试、上传或删除操作，再备份数据库和复制历史目录。确认没有活动模型测试后，`model-test-work/` 无需备份；若在活动测试期间备份，有效的固定权重副本必须与数据库状态保持同一时点。服务器列表和采样会随数据库迁移，远程 Agent 的中心地址需另行更新。

## 开发检查与排障

以下两组命令分别从项目根目录进入对应子目录执行。后端测试使用临时数据库和输出目录：

```bash
cd web/backend
test_data_root="$(mktemp -d)"
PLATFORM_DATA_ROOT="$test_data_root" \
PLATFORM_RUNS_ROOT="$test_data_root/runs" \
PLATFORM_RUNTIME_ROOT="$test_data_root/task_runtime" \
PLATFORM_LOG_ROOT="$test_data_root/log" \
DATABASE_URL="sqlite:///$test_data_root/test-platform.db" \
python -m pytest -q tests
```

```bash
cd web/frontend
npm run lint
npm run build
```

现有后端测试覆盖任务操作、运行记录、数据集、健康接口、参数校验、节点认证、Agent 恢复、领取竞态、workspace 协调与文件操作等。发布前应以当前 checkout 重新执行的 `pytest`、lint 和生产构建结果为准，不沿用旧版本的测试数量。后端测试通过仍不代表真实 GPU/DDP 和跨服务器网络故障已经验收。

| 现象 | 判断与处理 |
| --- | --- |
| 日志复制无反应或下载不完整 | 先核对上面的日志控件限制，完整输出从执行服务器获取 |
| 本机 GPU 空闲但任务一直排队 | 检查本机其他活动任务是否申请了重叠 GPU；远程同编号 GPU 不会占用本机设备 |
| 远程节点在线但一直“启动中” | 先确认中心与 Agent 均为配套的 1.8.0，再核对 `training.ready`、确认重试日志、`.training-state/active/` 和输出根锁 |
| 远程任务一直“正在停止” | 到远程服务器确认当前 Attempt 的 YOLO 进程已结束；停止至少 30 秒后可在训练画布解除占用，该操作不会远程杀进程 |
| 本机重启后显示“已中断” | 平台会按完整命令和进程启动时间尝试重新接管；显示已中断说明匹配失败，应核对事件、残留进程和检查点 |
| 清理请求返回但记录仍在 | 202 仅表示受理；查看回收站进度、失败原因和 Agent 在线状态 |

详细证据和改进优先级见 [项目分析](../docs/project-analysis.md)，服务日志及备份操作见 [部署说明](deploy/README.md)。

## 安全边界

- 模型只能从项目的 `models/`、`pt/` 或 `ultralytics/weights/` 选择。
- 数据集配置只能从项目的 `数据集/` 或 `ultralytics/xl/` 选择。
- 训练命令使用参数数组执行，不调用 Shell。
- 产物下载必须位于对应任务的训练目录内。
- 面向非受信网络部署前，应在 Nginx 或统一网关增加身份认证和 HTTPS。
- 当前管理页面和 API 没有内置登录认证；Agent Token 只验证对应节点的监控、训练和文件操作接口，不能替代管理入口的访问认证。
- 远程文件由对应 Agent 校验和处理，不在中台解释远程绝对路径；远程目录边界由 Agent 的允许目录配置限定。
- Agent 配置包含专属 Token，应设置权限为 `600`，不提交到 Git；Agent 不跟随 HTTP 重定向，HTTPS 默认验证证书。
